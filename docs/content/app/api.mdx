# App 接口

App 通道的方法都挂在 `app` 上，命名沿用「域 + 动作」的短动词形式。除登录相关方法外，返回值统一是服务端原始结构（`Record<string, unknown>`），字段与 Android 客户端一致。

<Note>
App 接口依赖 `X-Tt-Token` 等登录态。未登录时只有 `device()`、`code()`、`slide()`、`sms()`、`pwd()`、`qr()`、`mfa()` 可用。
</Note>

## 会话参数

凡涉及会话的方法都接收同一组 `ConvId` 字段：

| 字段 | 说明 |
|------|------|
| `conversationId` | 会话字符串 id，可在收侧消息上直接取 |
| `shortId` | int64 会话短 id，用字符串或数字传；合并转发必填 |
| `type` | `1` 单聊 / `2` 群聊 |

所有 int64（消息 id、游标、`shortId`）都用字符串传递，避免超过 `Number.MAX_SAFE_INTEGER` 后精度丢失。消息收发、媒体上传与合并转发限制见 [App 消息](/docs/app/message)。

## 登录与设备

| 方法 | 用途 |
|------|------|
| `device(opts?)` | 注册并激活设备，返回 `Ids` |
| `code(mobile)` | 只发送验证码，1105 时返回 `captcha` |
| `slide(opts?)` | 为当前滑块挑战起本地验证页 |
| `sms(opts)` | 短信验证码登录（含滑块与二次验证；未完成） |
| `pwd(opts)` | 密码登录（未完成） |
| `qr(opts?)` | 扫码登录（自动换码、合并会话） |
| `mfa(kind, input?)` | 手动提交二次验证：`sms` / `password` / `upsms` / `qr` |
| `info()` | 账号信息 |
| `token()` | 当前 Cookie 与 uid |
| `record(status)` | 开启/关闭「保存登录信息」 |
| `key()` | keyhub 握手得到的 IM 密钥 |
| `im(call?)` | 直接调用 IM 加密 pb 接口 |
| `ee(id?)` | 导出 ee.info 96B key 包 |
